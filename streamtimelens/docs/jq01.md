# JQ-01 development contract

JQ-01 is opt-in and changes only query-time candidate selection. The default
Frozen Visual V2 path, snapshot format, ingestion, Top-K and final margin are
unchanged.

**Status: closed after the final structural revision.** Commit
`871836666c7ccfdf6dd80273f1b4583d597b9786` passed J1 and completed all 552
OOF observations, but r3 failed the preregistered stop conditions. No further
JQ feature, loss, head, threshold, or candidate adjustment is authorized.

## Current V2-original development priority

The active development target is the exact original Frozen Visual V2
`charades_sta_derived_dev_v1` benchmark, not a replacement dataset. The entry
point `scripts/run_jq01_v2_original_dev.py` reuses the frozen 1 MiB snapshots
and baseline rows for 100 videos and 219 queries, then evaluates the 552
stream-visible observations for which `gt_end <= t_q`. X1 candidate fitting and
JQ fitting are nested inside the same four whole-video OOF folds so an outer
held-out video's GT reaches neither generator nor ranker.

This benchmark is already consumed development data and may be iterated on.
D-lock preparation and J3 are intentionally deferred until a positive paired
V2-original result has first been established. They are not prerequisites for
this entry point.

The active and final structural revision is `v2-original-r3`. It replaces the
consumed r2 thresholded ridge with a fixed candidate-local temporal model:
ordered snapshot similarities are capped at 16 center tokens and eight tokens
for each two-second boundary neighborhood, then passed through separate GRUs.
The candidate state is compared with the Frozen V2 state and pool mean/max
context. Fixed heads jointly supervise IoU quality, candidate-minus-baseline
gain, left/right boundary quality, listwise rank, and baseline abstention. A
relative-regret term penalizes ranking a truly worse successor above the
baseline. Final selection is threshold-free stable argmax over the unchanged
Frozen V2 plus X1 Top-8 pool.

Example:

```bash
python3 scripts/run_jq01_v2_original_dev.py \
  --revision-id v2-original-r3 \
  --hypothesis 'candidate-local temporal boundary modeling improves gain transfer while protecting V2'
```

Revision `v2-original-r1` retained its complete failed gate record at commit
`cc83699bd11a75e94d2b4e852bc2efe7f64ef075`: the absolute-quality MLP raised
the benchmark's query-equal mIoU by `0.01172` and R@0.7 by `0.08926`, but its
video-equal mIoU delta was `-0.04714` because it replaced the baseline on 488
of 552 observations. The next revision therefore ranks candidate-minus-baseline
gain directly with a video-equal ridge fit and requires both predicted gain
`>0.03` and candidate/baseline geometric IoU `>=0.30`. These inputs are
snapshot-only; the thresholds are recorded as consumed-development choices.

Revision `v2-original-r2` at commit
`8574d67538e1256dba9b77129c15ff96793eb4e0` established the requested gain on
the original benchmark: standard query-equal mIoU changed from `0.392039` to
`0.400079` (`+0.008040`), video-equal paired mIoU changed by `+0.012637`, and
standard R@0.7 changed from `0.077899` to `0.121377` (`+0.043478`). Every rho
slice was nonnegative and all byte, snapshot, fold, baseline-identity and
provenance audits passed. This is consumed-development evidence, not an
independent claim. The broader gate remains open because good-baseline
video-equal delta was `-0.012673`, narrowly below its `-0.01` protection floor;
the 95% video-bootstrap mIoU interval also crosses zero. Per the current
priority, neither issue triggers D-lock work.

Revision r3 is the one structural upgrade authorized after r2. Its acceptance
contract requires standard mIoU above both `0.392039` and r2's `0.400079`,
positive video-equal mIoU, nonnegative standard R@0.7, every rho slice at least
`-0.02`, good-baseline video-equal delta at least `-0.01`, recoverable-delta
transmission at least 10%, and a positive 95% video-bootstrap mIoU lower bound.
If the complete OOF misses any condition, JQ-01 closes without a threshold,
width, loss-weight, or architecture follow-up.

The completed r3 result changed standard mIoU from `0.392039` to `0.384991`
(`-0.007048`) and standard R@0.7 from `0.077899` to `0.085145`
(`+0.007246`). Video-equal paired mIoU was `-0.014212` with 95% CI
`[-0.033842,+0.002364]`; video-equal R@0.7 was `-0.007583`;
good-baseline delta was `-0.047975`; recoverable-delta transmission was
`-4.30%`. The model retained Frozen V2 on 484/552 observations. Snapshot,
byte, fold, baseline-bit-exact and provenance checks all passed, so the result
is a model-quality failure rather than a protocol failure. D-lock was not
prepared or consumed.

The implementation is split into three stages:

1. `scripts/preregister_jq01_data.py` fixes the old non-formal observations as
   `development/consumed`, assigns stable whole-group outer folds, and
   separately selects an unseen D-lock. Both inventories contain identity,
   source-duration and content SHA fields only. Development may be reused;
   every D-lock cell needs at least eight videos.
2. `scripts/run_jq01_mechanism_gate.py` runs synthetic protocol tests only. It
   does not read effect data. Besides pytest output, it persists a complete
   nine-candidate score/feature/rank/selection trace and a before/after
   snapshot byte audit.
3. `scripts/run_jq01_oof.py` is the sole J2 entry for every revision. It requires a clean commit,
   verified immutable snapshots, the J0 `selection.jsonl` via
   `--j0-selection`, preregistered folds and an X1 provenance file
   that identifies revision `8f8c3f702146ab2f5a4c8a41877f5330a2973f90`,
   Top-8 and disabled X1 safety selection. `--revision-id` and `--hypothesis`
   identify the attempt. A later attempt receives the preceding
   `experiment_registry.json` through `--parent-registry` and writes a new
   immutable registry snapshot containing both old and new records.

All three scripts write below `work/results/<full-git-sha>/` through the shared
provenance helper. Every stage also writes `artifact_manifest.json`, which
records the byte count and SHA-256 of every completed artifact other than the
checksum index itself. The same J0 development selection is used by every J2
revision. J2 may be repeated; D-lock remains unseen until one revision is
chosen and frozen.

## J0 inventory format

Both inventory JSONL files contain `video_id`, `group_id`, `query_id`,
`source`, `duration_bucket`, and `content_sha256`. The development inventory
additionally contains the preserved `outer_fold`; folds are not reassigned
between revisions. Development is supplied with `--development-inventory` and
D-lock candidates with `--d-lock-inventory`. The exclusions JSON contains
exactly `video_ids`, `group_ids`, `query_ids`, and `content_sha256`; it lists
formal and any other identities forbidden from development or D-lock.

Development annotations may already be known and can be used repeatedly. The
D-lock inventory stays effect-blind and must have zero video, group, query and
content-SHA overlap with development.

## J2 observation format

The OOF input is JSONL. Each row must contain exactly:

`observation_id`, `video_id`, `group_id`, `query_id`, `content_sha256`,
`budget_bytes`, `rho`, `source`, `duration_bucket`, `good_baseline`, `snapshot_path`, `query_embedding`,
`baseline_row`, `gt_span`, `x1_candidates`, and `outer_fold`.

Each X1 candidate contains exactly `candidate_id`, `start_s`, `end_s`, `score`
and `frame_refs`. The companion provenance JSON is:

```json
{
  "artifact_sha256": "<SHA-256 of the observation JSONL>",
  "generator_source_revision": "8f8c3f702146ab2f5a4c8a41877f5330a2973f90",
  "safety_selector_used": false,
  "top_k": 8
}
```

`query_id` and `content_sha256` must match the J0 identity exactly; the snapshot
manifest's `video_id`, byte budget, and `t_q / duration` must match the row as
well. `gt_span`, source and good-baseline are held by the evaluation layer. The
selector receives only the verified snapshot, query embedding, candidate
geometry, rho and budget. Candidate targets appear only in OOF output rows
marked `training_or_evaluation_only=true`.

Example J2 revision arguments:

```bash
python3 scripts/run_jq01_oof.py \
  --observations prepared-development.jsonl \
  --x1-provenance x1-provenance.json \
  --j0-selection /path/to/J0/selection.jsonl \
  --revision-id jq-feature-v1-r1 \
  --hypothesis 'joint quality ranking transfers X1 oracle gain' \
  --first-revision
```

For the next revision, add
`--parent-registry /path/to/r1/experiment_registry.json`. Prior result
directories and failed records are never modified or deleted.

J2 writes the complete outer/inner train, validation and held-out video/group
lists and their SHA-256 values, per-observation candidate tables, immutable
snapshot fingerprints and byte totals, fold checkpoints/scalers, paired gate
summaries, and the append-only experiment registry. Snapshot, byte, fold,
baseline-bit-exact and provenance checks are derived from these audits rather
than supplied as unconditional flags.
